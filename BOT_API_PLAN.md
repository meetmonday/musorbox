# Совместимость Musorgram с Telegram-ботами

## Цель

Добавить в MusorBox ограниченный Telegram Bot API-совместимый интерфейс, чтобы существующие
боты могли работать в личных и групповых чатах Musorgram без переписывания обработчиков.
Первый целевой бот — `../node-trashkek`. Это не реализация MTProto и не обещание полной
совместимости со всеми методами Telegram.

## Архитектура

- Бот является отдельным локальным пользователем `users` и отмечается записью `message_bots`.
- Bot token показывается один раз, в БД хранится только SHA-256-хеш.
- Внешний interface повторяет Bot API: `/telegram-bot-api/bot<TOKEN>/<method>`.
- Входящие события хранятся в долговременной очереди `message_bot_updates`; номер строки — `update_id`.
- Long polling реализуется через `getUpdates`, а не через клиентский SSE Musorgram.
- Собственные сообщения и сообщения других ботов не возвращаются боту, чтобы не создавать циклы.
- Токены редактируются в HTTP-логах; подробный long-poll лог включается через `BOT_API_DEBUG=1`.

## Этапы

### Этап 1 — текстовый Bot API

- [x] таблицы ботов и очереди updates;
- [x] CLI создания бота;
- [x] `getMe`;
- [x] пустой/durable `getUpdates` с long polling и offset;
- [x] постановка личных и групповых сообщений в очередь;
- [x] Telegram `message` и `bot_command` entities;
- [x] `sendMessage`;
- [x] `sendChatAction` как безопасный no-op;
- [x] настройка `BOT_API_BASE_URL` в `node-trashkek`;
- [x] редактирование токенов и диагностические логи.

### Этап 2 — изображения

- [ ] `sendPhoto`;
- [x] `sendMediaGroup` для фото по URL и multipart `attach://`;
- [ ] `getFile` и файловый endpoint;
- [x] безопасная загрузка URL с защитой от SSRF и лимитами;
- [x] преобразование альбомов между моделями Telegram и Musorgram.

### Этап 3 — replies и удаления

- reply-связи в схеме, API и клиентах;
- `reply_parameters`, `reply_to_message`, `deleteMessage`;
- до полноценного удаления `deleteMessage` отвечает успешным безопасным no-op и пишет предупреждение;
- явные разрешения ботов на удаление чужих сообщений в группах.

### Этап 4 — универсальные вложения

- документы, видео, аудио, превью и их отображение во Flutter.

### Этап 5 — расширенная совместимость

- inline query, редактирование, typing, клавиатуры/callback query, webhook.

## Критерии готовности

1. [x] Создаётся `trashkek_bot` и выдаётся токен.
2. [x] Бот может быть добавлен в группу существующей формой по логину.
3. [x] `node-trashkek` запускается с локальным `BOT_API_BASE_URL`.
4. [x] `getMe` проходит, GramIO пишет `Running as @trashkek_bot` и начинает long polling.
5. [x] `/dora`, `/ver` и `/hsites` отвечают в личке и группе.
6. [ ] Обработчик `#div_comment_` присылает ответ.
7. [ ] После перезапуска доставляются неподтверждённые updates.
8. [ ] Подтверждённый offset не обрабатывается повторно.
9. [ ] Ответы появляются во Flutter через существующий SSE.
10. [x] Bot token отсутствует в HTTP-логах приложения.

## Поддержка `node-trashkek`

Текстовый этап полностью покрывает `/hsites`, `/ver`, `/dora` и текстовую часть обработчика
ссылок. `/hentai` с поиском и TikTok требуют медиа; `/verify` и `/pokupka` требуют replies и
файлов; `dotagosu` требует отдельного inline-интерфейса в клиенте.
